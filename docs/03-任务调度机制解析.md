# Betaflight 任务调度机制解析

## 1. 任务调度的总体流程

### 1.1 入口点

任务调度从 `main()` 函数开始：

```47:55:src/main/main.c
void FAST_CODE run(void)
{
    while (true) {
        scheduler();
#if defined(RUN_LOOP_DELAY_US) && RUN_LOOP_DELAY_US > 0
        delayMicroseconds_real(RUN_LOOP_DELAY_US);
#endif
    }
}
```

主循环不断调用 `scheduler()` 函数，这是整个任务调度的核心。

### 1.2 调度器核心逻辑

`scheduler()` 函数在 `src/main/scheduler/scheduler.c` 中实现，主要负责：

1. **实时任务处理**（优先级最高）
2. **普通任务调度**（基于优先级和时间的动态调度）

## 2. 实时任务的特殊处理

### 2.1 实时任务的定义

Betaflight 中定义了三个实时任务：
- `TASK_GYRO` - 陀螺仪采样
- `TASK_FILTER` - 滤波处理
- `TASK_PID` - PID控制循环

这些任务的优先级为 `TASK_PRIORITY_REALTIME`，在调度器中会被特殊处理。

### 2.2 实时任务的执行流程

在 `scheduler()` 函数中，实时任务的执行逻辑如下：

```516:561:src/main/scheduler/scheduler.c
    if (gyroEnabled) {
        // Realtime gyro/filtering/PID tasks get complete priority
        task_t *gyroTask = getTask(TASK_GYRO);
        nowCycles = getCycleCounter();
#if defined(UNIT_TEST)
        lastTargetCycles = clockMicrosToCycles(gyroTask->lastExecutedAtUs);
#endif
        nextTargetCycles = lastTargetCycles + desiredPeriodCycles;
        schedLoopRemainingCycles = cmpTimeCycles(nextTargetCycles, nowCycles);

        // ... 时间同步逻辑 ...

        // Once close to the timing boundary, poll for it's arrival
        if (schedLoopRemainingCycles < schedLoopStartCycles) {
            // ... 等待到时间边界 ...
            currentTimeUs = micros();
            taskExecutionTimeUs += schedulerExecuteTask(gyroTask, currentTimeUs);

            if (gyroFilterReady()) {
                taskExecutionTimeUs += schedulerExecuteTask(getTask(TASK_FILTER), currentTimeUs);
            }
            if (pidLoopReady()) {
                taskExecutionTimeUs += schedulerExecuteTask(getTask(TASK_PID), currentTimeUs);
            }
```

**关键点：**

1. **时间同步**：调度器会等待到预定的时间边界（`nextTargetCycles`），然后执行实时任务
2. **条件执行**：`taskFiltering` 和 `taskMainPidLoop` **不是**每次都会执行，而是通过 `gyroFilterReady()` 和 `pidLoopReady()` 来判断

## 3. taskFiltering 和 taskMainPidLoop 的执行条件

### 3.1 控制机制

这两个任务的执行由 `pidUpdateCounter` 和 `activePidLoopDenom` 控制：

```1326:1351:src/main/fc/core.c
FAST_CODE void taskGyroSample(timeUs_t currentTimeUs)
{
    UNUSED(currentTimeUs);
    gyroUpdate();
    if (pidUpdateCounter % activePidLoopDenom == 0) {
        pidUpdateCounter = 0;
    }
    pidUpdateCounter++;
}

FAST_CODE bool gyroFilterReady(void)
{
    if (pidUpdateCounter % activePidLoopDenom == 0) {
        return true;
    } else {
        return false;
    }
}

FAST_CODE bool pidLoopReady(void)
{
    if ((pidUpdateCounter % activePidLoopDenom) == (activePidLoopDenom / 2)) {
        return true;
    }
    return false;
}
```

### 3.2 工作原理

假设 `activePidLoopDenom = 4`（典型配置，表示PID处理分母为4）：

| pidUpdateCounter | gyroFilterReady() | pidLoopReady() | 执行的任务 |
|-----------------|-------------------|----------------|-----------|
| 0 | ✅ true | ❌ false | taskGyroSample + taskFiltering |
| 1 | ❌ false | ❌ false | taskGyroSample  |
| 2 | ❌ false | ✅ true | taskGyroSample + taskMainPidLoop |
| 3 | ❌ false | ❌ false | taskGyroSample  |
| 4 → 0 | ✅ true | ❌ false | taskGyroSample + taskFiltering |
| ... | ... | ... | ... |

**时序图：**

```
时间轴:  ──────────────────────────────────────────>
任务执行:
         [GYRO] [GYRO] [GYRO] [GYRO] [GYRO] ...
         [FILTER]              [FILTER]              ...
                   [PID]                  [PID]      ...
计数器:   0      1      2      3      0      1      ...
```

### 3.3 回答您的问题

**Q: taskFiltering 之后，taskMainPidLoop 一定会被执行吗？**

**A: 不一定！** 这两个任务不是顺序执行的：

1. `taskFiltering` 在 `pidUpdateCounter % activePidLoopDenom == 0` 时执行
2. `taskMainPidLoop` 在 `pidUpdateCounter % activePidLoopDenom == activePidLoopDenom/2` 时执行
3. 它们是**交错执行**的，而不是先后顺序执行

## 5. 时间戳控制任务执行

### 5.1 时间驱动的任务

对于时间驱动的任务，调度器通过以下方式控制：

1. **期望执行周期**（`desiredPeriodUs`）：每个任务定义期望的执行周期
2. **最后执行时间**（`lastExecutedAtUs`）：记录任务上次执行的时间戳
3. **任务年龄**（`taskAgePeriods`）：计算任务已经延迟了多少个期望周期

```728:733:src/main/scheduler/scheduler.c
                } else {
                    // Task is time-driven, dynamicPriority is last execution age (measured in desiredPeriods)
                    // Task age is calculated from last execution
                    task->taskAgePeriods = (cmpTimeUs(currentTimeUs, task->lastExecutedAtUs) / task->attribute->desiredPeriodUs);
                    if (task->taskAgePeriods > 0) {
                        task->dynamicPriority = 1 + task->attribute->staticPriority * task->taskAgePeriods;
```

**工作原理：**

- 如果任务上次执行后已经过了 `desiredPeriodUs`，则 `taskAgePeriods >= 1`
- 任务延迟的时间越长，`taskAgePeriods` 越大，动态优先级越高
- 这样可以防止任务饥饿（starvation）

### 5.2 事件驱动的任务

对于事件驱动的任务，通过 `checkFunc` 来判断是否执行：

```710:726:src/main/scheduler/scheduler.c
                // Task has checkFunc - event driven
                if (task->attribute->checkFunc) {
                    // Increase priority for event driven tasks
                    if (task->dynamicPriority > 0) {

                        task->dynamicPriority = 1 + task->attribute->staticPriority * task->taskAgePeriods;

                        task->taskAgePeriods = 1;

```

## 6. 总结

### 6.1 关键要点

1. **主循环**：`main() → run() → scheduler()` 不断循环
2. **实时任务**：`TASK_GYRO` 总是执行，`TASK_FILTER` 和 `TASK_PID` 根据计数器条件执行
3. **执行条件**：
   - `taskFiltering`: `pidUpdateCounter % activePidLoopDenom == 0`
   - `taskMainPidLoop`: `pidUpdateCounter % activePidLoopDenom == activePidLoopDenom/2`
4. **时间控制**：通过 `lastExecutedAtUs` 和 `desiredPeriodUs` 计算任务延迟，动态调整优先级
5. **调度策略**：实时任务优先 + 基于优先级的普通任务调度

### 6.2 实际调用链

```
main()
  └─> run()
       └─> scheduler()  [不断循环]
            ├─> 实时任务处理（gyroEnabled == true）
            │    ├─> schedulerExecuteTask(gyroTask)
            │    │     └─> taskGyroSample()
            │    │           └─> gyroUpdate() + pidUpdateCounter++
            │    ├─> if (gyroFilterReady())
            │    │     └─> schedulerExecuteTask(filterTask)
            │    │           └─> taskFiltering()
            │    └─> if (pidLoopReady())
            │          └─> schedulerExecuteTask(pidTask)
            │                └─> taskMainPidLoop()
            │                      ├─> subTaskRcCommand()
            │                      ├─> subTaskPidController()
            │                      ├─> subTaskMotorUpdate()
            │                      └─> subTaskPidSubprocesses()
            └─> 普通任务调度
                 └─> 根据优先级和延迟时间选择任务
                      └─> schedulerExecuteTask(selectedTask)
```

这样设计的目的是：
- **保证实时性**：陀螺仪采样和PID控制需要精确的时间间隔
- **提高效率**：滤波和PID不需要每次都执行，可以降低CPU负载
- **灵活性**：普通任务可以根据系统负载动态调度
