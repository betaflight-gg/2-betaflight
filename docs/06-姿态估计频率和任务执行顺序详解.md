# 姿态估计频率和任务执行顺序详解

## 问题1：如果acc采样频率是3.2kHz，姿态估计频率是多少？

### 答案

**姿态估计频率 = acc.sampleRateHz / imu_process_denom**

如果：
- `acc.sampleRateHz` = 3200 Hz（和gyro一样）
- `imu_process_denom` = 2（默认值）

那么：
- **姿态估计频率 = 3200 / 2 = 1600 Hz**

### 代码依据

```1091:1098:src/main/fc/core.c
    if (FLIGHT_MODE(ANGLE_MODE | ALT_HOLD_MODE | POS_HOLD_MODE | HORIZON_MODE)) {
        LED1_ON;
        // increase frequency of attitude task to reduce drift when in angle or horizon mode
        rescheduleTask(TASK_ATTITUDE, TASK_PERIOD_HZ(acc.sampleRateHz / (float)imuConfig()->imu_process_denom));
    } else {
        LED1_OFF;
        rescheduleTask(TASK_ATTITUDE, TASK_PERIOD_HZ(100));
    }
```

**默认配置：**
```127:127:src/main/flight/imu.c
    .imu_process_denom = 2,
```

### 频率对比表

| 场景 | acc.sampleRateHz | imu_process_denom | 姿态估计频率（角度模式） | 姿态估计频率（非角度模式） |
|------|------------------|-------------------|------------------------|--------------------------|
| **典型配置** | 1000 Hz | 2 | **500 Hz** | 100 Hz |
| **您的配置** | 3200 Hz | 2 | **1600 Hz** | 100 Hz |
| **您的配置（denom=1）** | 3200 Hz | 1 | **3200 Hz** | 100 Hz |
| **您的配置（denom=4）** | 3200 Hz | 4 | **800 Hz** | 100 Hz |

**PID任务内部顺序：**
1. **subTaskRcCommand** - 处理遥控器命令
2. **subTaskPidController** - PID控制器（包含角度环和角速度环）
3. **subTaskMotorUpdate** - 混控输出（电机PWM/DShot）
4. **subTaskPidSubprocesses** - PID后处理（如TPA更新等）

## 完整执行顺序图

### 时间线（以3.2kHz PID为例）

```
时间轴（312.5μs周期）─────────────────────────────────────────────→

实时任务周期 #1 (0μs)
├─ [实时任务区域 - 最高优先级]
│  ├─ TASK_GYRO (3.2kHz)
│  │  └─ gyroUpdate() - 读取陀螺仪原始数据
│  │
│  ├─ TASK_FILTER (条件执行，如1.6kHz)
│  │  └─ taskFiltering() - 陀螺仪滤波处理
│  │
│  └─ TASK_PID (条件执行，如3.2kHz)
│     ├─ subTaskRcCommand() - 处理遥控器
│     ├─ subTaskPidController() - PID计算
│     │  ├─ 读取attitude数据（由姿态估计任务更新）
│     │  ├─ 角度环计算（如果启用）
│     │  └─ 角速度环计算
│     ├─ subTaskMotorUpdate() - 混控输出
│     │  └─ 电机PWM/DShot输出
│     └─ subTaskPidSubprocesses() - PID后处理
│
└─ [普通任务调度区域 - 在实时任务之后]
   └─ 调度器根据优先级和时间选择任务
      ├─ TASK_RX (HIGH优先级，33Hz)
      ├─ TASK_DISPATCH (HIGH优先级，1000Hz)
      ├─ TASK_ACCEL (MEDIUM优先级，1000Hz)
      ├─ TASK_ATTITUDE (MEDIUM优先级，1600Hz角度模式/100Hz非角度模式) ← 姿态估计在这里
      └─ 其他任务...

实时任务周期 #2 (312.5μs)
├─ [实时任务区域]
│  └─ ...
└─ [普通任务调度区域]
   └─ ...
```

### 关键点说明

1. **实时任务优先执行**
   - GYRO、FILTER、PID 在调度器中**优先且顺序执行**
   - 这些任务执行完后，才会调度普通任务

2. **姿态估计在实时任务之后**
   - ✅ **姿态估计不在实时任务中**
   - ✅ **姿态估计在混控输出之后**（因为混控在PID任务内部，而姿态估计是普通任务）
   - ✅ **姿态估计在gyro滤波之后**（因为gyro滤波是实时任务，优先执行）

3. **数据流方向**
   ```
   陀螺仪硬件 → TASK_GYRO → TASK_FILTER → TASK_PID (角度环/角速度环) → 混控输出
                                                      ↑
   加速度计硬件 → TASK_ACCEL ──────────────────────────┘
                                                      ↓
                                              TASK_ATTITUDE (姿态估计)
                                                      ↓
                                              更新attitude结构体
   ```

4. **数据同步问题**
   - PID任务在3.2kHz运行
   - 姿态估计在1600Hz运行（您的配置）
   - PID任务读取的`attitude`数据可能最多延迟 **1/1600 = 0.625ms**

## 总结

### 问题1答案

**如果acc采样频率是3.2kHz：**
- 姿态估计频率（角度模式）= **3200 / imu_process_denom**
- 默认情况下（imu_process_denom=2）：**1600 Hz**
- **不是500Hz**（500Hz是acc.sampleRateHz=1000时的值）

### 问题2答案

**任务执行顺序：**

1. **实时任务（严格顺序）：**
   - GYRO采样 → GYRO滤波 → PID计算（包含角度环） → **混控输出**

2. **普通任务（实时任务之后，动态调度）：**
   - 姿态估计在**混控输出之后**执行
   - 姿态估计在**gyro滤波之后**执行
   - 姿态估计是**独立任务**，优先级MEDIUM

**完整顺序：**
```
IMU读取(GYRO) → GYRO滤波 → PID计算(角度环+角速度环) → 混控输出 → [普通任务调度] → 姿态估计
```

**关键发现：**
- ✅ 姿态估计**不在实时任务中**，是普通任务
- ✅ 姿态估计在**混控输出之后**执行
- ✅ 姿态估计在**gyro滤波之后**执行
- ⚠️ 存在数据延迟：PID任务读取的角度数据可能延迟最多0.625ms（1600Hz姿态估计）
